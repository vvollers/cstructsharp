# Schema-by-schema review

Reviewed all 184 detector registrations and the additional DLL sample. **110 registrations expanded**, sharing implementations where their outer container is identical. The other 74 keep their existing layout; the table records the reason and useful future candidates. Retained does not mean further parsing is impossible.

Expansions live in [schema-expansions.ts](src/schema-expansions.ts), applied by [schemaForFile](src/detected-schemas.ts) during detection or when loading an unedited schema template. Each generated schema describes its actual coverage. The nine sample-backed demonstrations remain synchronized with their managed-library fixtures: their deliberately small sample bytes cannot demonstrate later records. Use **Load & detect** on a real file for the expanded layout.

## Language review

The layouts demonstrate enums, low-bit-first bitfields (including 64-bit FLAC fields), nested structures, runtime-length arrays, multidimensional float arrays, signed values, explicit byte order and typed 32/64-bit pointers. File-selected schemas handle optional fields and tagged variants. The language itself does not implement conditional fields, loops, varints, decompression or arbitrary tagged unions inside structs. No artificial unions or invalid pointer conversions were introduced to make a layout look more complex.

Scans use at most the first 64 KiB, with 16 ZIP/FLAC records, 32 chunks/packets/sections or 128 ELF table entries/STL triangles. Typed pointers may read beyond that preview from the full loaded file. A zero-size ISO box means actual EOF, so only its header is exposed. Compressed/encrypted bodies stay opaque. These are inspection layouts, not validators or complete decoders. Reload detection after changing format-defining bytes.

## Verification

Every registration is compiled by the real WASM runtime. Value-level browser tests cover FLAC bitfields, ZIP flags/payload, ELF pointer tables, STL floats/vertices, GLB JSON, PNG chunks, RIFF chunks, OpenType head pointers, WebAssembly sections and Zstandard descriptor widths. The optional upstream audit records read errors separately from schema compilation errors; detector fixtures can be truncated.

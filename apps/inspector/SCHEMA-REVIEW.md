# Standalone schema audit

All 184 detector registrations use fixed declarations. This replaces the earlier preview-expansion audit: input-dependent record counts, offsets, variant selection and region discovery have been removed. The nine sample-backed demonstrations retain their managed fixtures. The additional DLL entry shares the PE sample definition.

The source of truth is [schema-catalog.ts](src/schema-catalog.ts), which registers each format's extensions, detection layout and optional sample examples together. No module receives file bytes to construct a layout. Each editor definition is self-contained and formatted.

## Language features and text

Examples use nested structs, enums, low-bit-first bitfields, counted arrays, multidimensional float arrays, explicit byte order and typed pointers. Native conditions select supported variants. ZIP filenames use UTF-8 or CP437 according to bit 11; PNG tEXt uses Latin-1; ASAR uses bounded UTF-8; registry hive names use UTF-16LE code units. Raw char arrays retain one-byte code units. Encoded/compressed payloads are not interpreted as text unless their format identifies an encoding.

See the common-format coverage below for detailed boundaries, pointers, tests and specifications. Large-file address reach is independent of decoded-data budgets; see the [large-file guide](../../docs/guides/browser/large-data.md).

## Common-format coverage

These are standalone library examples. Copy the editor text and use the displayed byte order, pointer width and
root type. The inspector passes that text once to the library against the full source. `if` and `switch` choose
stored variants; arrays use earlier counts; typed pointers follow stored offsets. There are no discovered regions,
input-dependent declarations, injected file offsets, or merged parse trees.

The PNG/JPEG eight-record limits are visible in the definitions, not hidden library limits. Extra sequential fields
with the same stop condition can extend those examples. The language has counted arrays but no repeat-until-EOF
construct. These examples do not claim complete format support. Malformed sizes can cause an ordinary read or
budget error; a successful parse is not validation of the whole container.

**Load & detect** selects these fixed profiles. The small sample buttons retain the nine original teaching
fixtures. **Load file** preserves whichever definition is in the editor. This makes variant experiments repeatable:
change bytes or load another file and let the same library conditions choose the branch.

### Why file offsets and pointers differ

A C pointer in a running program normally identifies a virtual-memory address in that process. A disk file cannot
reuse that address reliably in another process. Formats therefore store offsets: numbers measured from the start
of a file, a container or another defined origin. CStructSharp interprets a typed pointer according to the selected
addressing mode, seeks to its target, reads the declared type, and restores the containing record's position.
It does not allocate or read the gap between two offsets.

PE is an instructive distinction: a section's raw-data offset is a file offset, but most data-directory addresses
are RVAs, measured in the executable's loaded virtual image. Sections can have different file and virtual positions.
Treating an RVA as a file pointer would silently read the wrong bytes. The example preserves RVAs as numeric values.

The pointer setting describes the bytes stored in the format. An eight-byte offset can reach beyond 4 GiB on a
64-bit seekable source; a four-byte unsigned offset cannot represent such a position, regardless of the host OS.
The inspector's Blob reader and the managed stream parser keep file length separate from decoded data size.
See the [large-file guide](../../docs/guides/browser/large-data.md#scattered-pointers-and-read-budgets).

### Verification and sources

Browser tests execute these definitions in the real WASM runtime, including changed native branches, metadata
past 64 KiB, PE section pointers, 129 STL triangles, and multiple linked pointers past 4 GiB. Managed regression
tests follow forward and backward pointers beyond 8 TiB with default options and under a 512-byte read budget.

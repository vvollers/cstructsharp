# Managed quality projects

`CStructSharpTests/` contains unit, regression, property, concurrency, and fixture tests and is also the source of explorer demonstrations. `CStructSharp.Generators.Tests/` runs the source generator in memory: golden `Snapshots/*.g.cs` compared byte for byte (`UPDATE_SNAPSHOTS=1 dotnet test ...` rewrites them; the diff is reviewed in the commit), reader/writer/conditional parity against the runtime, analyzer, option, and mapped-class tests. `CStructSharp.Generated.Parity/` compiles every repository layout fixture with the generator (`Layouts.g.cs` and `layouts.json` from `node tools/quality/generate-parity-layouts.mjs`; `--check` in CI) and compares values, bytes, addresses, and truncation failures with the runtime. `CStructSharp.Fuzz/` contains bounded fuzzing (including the generated-differential target) and the tracked replay corpus. `CStructSharp.AotConsumer/` publishes with `PublishAot` and runs typed reads, generated layouts, and mapped classes. `CStructSharp.PackageConsumer/` and `CStructSharp.Memory.PackageConsumer/` check an actual NuGet package (the first with a generated layout and a `.cstruct` file) and deliberately stay outside initial solution restore. Run `dotnet test tests/CStructSharpTests/CStructSharpTests.csproj -c Release` at the repository root, and the two generator projects the same way. Tests consume reviewed inputs from `contracts/`; do not regenerate expectations to hide regressions. Reports and build outputs are ignored.
